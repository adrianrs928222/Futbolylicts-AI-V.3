# v0.7 — The Odds API como fuente exclusiva de cuotas

> **Documento histórico.** Las reglas canónicas vigentes están en `docs/RULES.md` y `docs/FUTBOLYLICTS_PROMPT.md`.


## Objetivo

Evitar duplicar funciones entre proveedores y gastar llamadas innecesarias.

### Reparto de funciones

- API-Football: datos deportivos.
- The Odds API: cuotas.
- Supabase: caché, histórico y contadores.
- Futbolylicts-AI: decide.

## Ahorro de créditos

1. API-Football descarga los fixtures del día.
2. La web filtra reservas/juveniles/femenino/amistosos localmente.
3. Solo profundiza por defecto en 12 partidos.
4. Futbolylicts calcula qué mercados parecen más prometedores sin pedir aún cuotas.
5. Solo los 7 mejores partidos pasan a la capa de cuotas.
6. Para cada partido se consultan como máximo 2 familias de mercado.
7. `/sports` y `/events` de The Odds API se usan para resolver liga/evento y se cachean.
8. Las cuotas se cachean 10 minutos en memoria + Supabase.

## Familias de mercado soportadas desde The Odds API

- `h2h` → ganador
- `double_chance` → 1X / X2 / 12
- `totals` → líneas principales de goles
- `alternate_totals` → +0.5 / +1.5 / +2.5 cuando estén disponibles
- `btts` → ambos marcan
- `alternate_team_totals` → goles de equipo

No se solicitan hándicaps.

## Bet365

Por defecto:

```env
THE_ODDS_BOOKMAKERS=bet365
```

También se mantiene compatibilidad con:

```env
PREFERRED_BOOKMAKER=Bet365
```

No hay fallback automático a otro bookmaker.

## Presupuesto

```env
THE_ODDS_API_DAILY_CREDIT_BUDGET=14
THE_ODDS_MAX_FIXTURES_TO_PRICE=7
THE_ODDS_MAX_MARKETS_PER_FIXTURE=2
```

El contador local/Supabase es conservador: reserva antes de llamar para evitar carreras entre peticiones.

## Actualización de Supabase

Usuarios de v0.6 deben ejecutar:

`supabase/migrations/v0.7_the_odds_api.sql`

El proyecto sigue funcionando sin esa migración mediante contador local, pero la protección persistente entre reinicios necesita la función nueva.
